# Mandatory service identities and real transport regression

Every database adapter requires expectedLogin. Direct group login is no longer accepted; all CI live adapters use separate NOINHERIT dedicated logins and group roles remain NOLOGIN after initial historical SQL fixtures. This is a breaking configuration change for callers without expectedLogin. The final audit also rejects LOGIN on any service group. Service pool configuration defaults to CA-pinned, hostname-verified TLS 1.2+ and rejects ambient connection and TLS downgrade settings; explicit loopback plaintext requires all of `VV_ALLOW_LOCAL_PLAINTEXT=1`, `VV_LIVE_TEST=1`, the disposable `verivaro_test` database name and loopback host, with no configured CA file. This path is test-only and is rejected for other database names or without the test marker.

CI provisions a disposable certificate authority and PostgreSQL certificate, starts server TLS and enforces hostssl for two synthetic logins. It verifies actual negotiated TLS via pg_stat_ssl, rejects an unrelated CA, hostname mismatch and plaintext connection, then provisions a replacement login, verifies it and retires the old one. The explicit admin-operated retirement helper disables login and clears password, removes intended role membership, terminates existing backends and checks none remain. It is not automatically called in production. An operator must first validate the fresh login and switch legitimate workers; use a distinct login per rotation, not password-only replacement. Run as authorized database administrator with exclusive change control. A post-commit termination failure is an incident: account remains disabled and must be independently reconciled. Existing distributed leases and in-flight work remain subject to incident reconciliation; retiring a database credential does not revoke external provider credentials or erase data already accessed. No actual production certificates or accounts changed.

Production requires trusted certificate/key provisioning, database hostssl rules, firewall/egress controls, independently supervised service processes, protected credential mounting and deployment review. Local CI is not independent production PKI or network validation.


## G1 credential retirement eligibility regression — draft-only

The administrator-operated `retireServiceCredential` preflight now requires **both** old and replacement identities to have exactly one permitted direct role membership, with `INHERIT FALSE`, `SET TRUE` and `ADMIN FALSE`. It rejects additional/transitive memberships (including PostgreSQL predefined broad-reading roles), an elevated or LOGIN-enabled group, direct database/schema CREATE grants, and an expired replacement identity. Results must identify the two exact intended logins; missing or duplicate rows fail closed. This is an extra defence before irreversible retirement DDL, not proof that the replacement has been independently authenticated and exercised. The operator still must verify the replacement connection, network TLS, app read/write behavior and recovery separately.

The real disposable-PostgreSQL TLS regression now injects both an additional `pg_read_all_data` membership and unexpected `ADMIN OPTION` for the proposed replacement; retirement must abort **before** disabling the old login. The test then removes the synthetic adverse grants and exercises the previously verified normal live retirement and old-session termination. No production credentials or Neon roles were modified.


## Direct privilege and default-grant retirement gate (G1 draft)

The administrator-only credential retirement preflight now checks for **explicit direct ACL grants and ownership** on non-system schemas, relations (including sequences), functions and types, in addition to `pg_default_acl` entries that would grant privileges to the retiring or replacement login on future objects. Direct database ACL grants are also rejected. Revoking a service role does not revoke these independent object-level privileges; permitting them would leave dormant authority attached to a retired principal or allow a replacement login to bypass the intended group-role boundary. PostgreSQL's system catalogues and ordinary default PUBLIC grants are not treated as direct login grants by these checks. This inventory is a defensive precondition, not a complete cluster-wide review of every PostgreSQL ACL-bearing object or a guarantee against future administrator grants.

The live synthetic TLS test deliberately adds direct schema USAGE, table SELECT, function EXECUTE and ALTER DEFAULT PRIVILEGES grants to the replacement identity, one by one. Each must reject retirement before modifying the old login; the original credential remains usable, the adverse grant is explicitly reversed, and normal replacement service operation is checked. Independent DBA review of the complete ACL/catalogue, credential custody and any race against a privileged administrator is still mandatory.
